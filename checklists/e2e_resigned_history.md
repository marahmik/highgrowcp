# E2E Checklist: 퇴사자 근무기록 관리자 조회

## Prerequisites
- [ ] 전체 관리자 계정과 매장 관리자 계정을 준비한다.
- [ ] 퇴사자 멤버십에 선택 월의 월초·월말 근무기록이 있다.
- [ ] 비교용으로 같은 사용자의 다른 매장 기록과 같은 매장의 다른 사용자 기록이 있다.

## Test cases

### 퇴사자 카드에서 기록 페이지 이동
**Given** 전체 관리자가 관리자 페이지의 직원관리 탭을 열었다.
**When** 퇴사자 카드의 `근무기록` 버튼을 누른다.
**Then** `/admin/resigned/:memberId/history`로 이동하고 대상 이름·매장·퇴사일을 표시한다.

- [ ] 활성 멤버 카드에는 `근무기록` 버튼이 없는지 확인한다.
- [ ] 퇴사자 카드에는 `근무기록` 버튼이 있는지 확인한다.
- [ ] 이동한 URL에 선택한 `store_members.id`가 포함되는지 확인한다.

### 월별 기록 조회
**Given** 유효한 퇴사자 기록 페이지를 열었다.
**When** 월을 선택하거나 이전·다음 달로 이동한다.
**Then** 해당 사용자·매장·월의 기록만 조회 전용 일정표에 표시한다.

- [ ] 선택 월 1일과 말일 기록이 표시되는지 확인한다.
- [ ] 이전 달 말일과 다음 달 1일 기록이 제외되는지 확인한다.
- [ ] 같은 사용자의 다른 매장 기록과 같은 매장의 다른 사용자 기록이 제외되는지 확인한다.
- [ ] 셀을 눌러도 편집 UI가 열리지 않는지 확인한다.
- [ ] `work_type`이 있는 표시 기록 수와 월 총 근무 합계가 같은지 확인한다.
- [ ] 기록 없는 달에서 빈 일정표와 `0일`을 표시하는지 확인한다.

### 접근 제어와 잘못된 대상
**Given** 상세 URL을 알고 있다.
**When** 권한 또는 멤버십 상태가 다른 사용자로 직접 접근한다.
**Then** 권한 없는 데이터는 렌더링하지 않는다.

- [ ] 매장 관리자 계정은 `/my`로 이동하고 상세 데이터 요청이 시작되지 않는지 확인한다.
- [ ] 존재하지 않는 멤버십 ID는 오류 상태를 표시하고 스케줄을 요청하지 않는지 확인한다.
- [ ] `role!='resigned'`인 멤버십 ID는 오류 상태를 표시하고 스케줄을 요청하지 않는지 확인한다.

## Edge cases
- [ ] 퇴사일이 없는 퇴사자도 페이지를 조회할 수 있다.
- [ ] 느린 네트워크에서 월을 빠르게 전환해도 이전 응답이 최종 월을 덮어쓰지 않는다.

## Known limitations
- 자동 테스트 인프라가 없어 이 체크리스트는 수동 E2E로 실행한다.
- 기존 RLS의 매장 관리자 데이터 조회 범위 재설계는 이번 UI 변경 범위 밖이다.
